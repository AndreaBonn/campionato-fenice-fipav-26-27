# campionato-fenice-fipav-26-27

Static page (GitHub Pages, `docs/`) for ASD Fenice's Seconda Divisione Femminile 2026/27 games (FIPAV Cagliari, girone 64444), kept in sync with FIPAV Online by a scheduled GitHub Action.

The project started as a selective copy of the sister basketball project `campionato-serie-c-26-27` (same pipeline, different source), not a fork. Requirements, plan and task checklist are in `specs/001-fenice-seconda-divisione/` (`spec.md`, `plan.md`, `tasks.md`).

## Data flow

FIPAV Online JSON API (girone `64444`) + `data/calendario-iniziale.json` (baseline) + fipavcagliari.it WordPress posts and FIPAV poster index → `src/fenice_calendar` → `docs/data.json` → `docs/index.html`.

- Source: `data.fipavonline.it` first, `app.fipavonline.it` on the same resource as fallback (`fetch.py`). A response whose content type is not JSON (the Cloudflare challenge page is HTML) is rejected like a network error; when both hosts fail the run raises `FetchError`. Requests are 1 s apart and carry a project User-Agent. Resources: calendar (`/api/v2/calendar/0/{group}`), tables (`/api/v2/tables/{group}`), posters (`/public/locandine/19092.json`).
- The Fenice is identified only by `cod_aff_societa` `190920448` (`TEAM_COD` in `config.py`), never by team id or name: the team id changes from one group to another. If the code is not in the calendar the run fails.
- The calendar's `date` and `time` fields are authoritative; `ts_gara` is not used.
- `data.json` follows the schema in `plan.md` § Schema di data.json (version 1), checked by `validate_data()` in `schema.py`, which also rejects unexpected keys and inconsistent data. `Notice.kind` is a `Literal` (`NoticeKind`) checked by `validate_data()`.
- Python constants live once in `config.py` (`LOCAL_TZ`, `TIMEZONE_NAME`, `LAT_LIMIT`, `LNG_LIMIT`, `ICS_UID_DOMAIN`, `TEAM_DISPLAY_NAME`, plus the URLs, `TEAM_COD`, `FORMULA`): modules import them, none redefines them.
- Games carry `referee_pending`, true for a game still to play until a real referee name is published (the FIPAV placeholder `DESIGNATO` does not count; a played game is never pending, checked by `validate_data`), and `changes`: the fields (`date`, `time`, `venue`) that differ from `data/calendario-iniziale.json` (`merge.py`). Games are matched to the baseline by FIPAV game id.
- Standings (`parse_standings`) are the FIPAV rows as published, penalties included. FIPAV counts games that are not yet homologated too (measured 2026-11-21 on girone 64353), so the page treats the table as the official one and does not recompute it from results. Only while FIPAV publishes no standings at all (empty `standings`) `tables-view.js` shows the table rebuilt from the played games (`tableFromGames`): a deliberate fallback (user decision of 2026-11-21).
- Notices (`notices.py`) come from the fipavcagliari.it WordPress API (`WP_POSTS_URL`): the "Indizioni" category (id 3) plus a search on "seconda divisione", only posts from `NOTICES_SINCE` (2026-08-01), at most `NOTICES_MAX` (10), links restricted to fipavcagliari.it over https. Each notice has `kind` (`seconda-divisione` or `indizione`). Posters (`posters.py`) are the game flyers from the FIPAV poster index, kept only if the key matches `POSTER_KEY_RE`. Both live in `enrich.py`: an outage is not fatal, the previous notices and posters in `docs/data.json` are kept.
- The league formula is not published: `FORMULA` in `config.py` is empty (`published: false`, no promotion, playoff or relegation zones) and the tie-break is marked provisional (`TIE_BREAK`: wins, set ratio, point ratio). Update `FORMULA` and the page once the Comitato publishes the "indizione".
- `docs/calendario.ics` (`ics.py`) is the subscribable feed (Europe/Rome, 2-hour events, stable UID per game). `SEQUENCE` stays 0 on purpose (user decision of 2026-11-21): subscribed calendars reread the whole feed and update events by UID; a per-game counter in data.json is the fix if a client ever keeps a moved game at its old time; written only when the content changes, the per-run `DTSTAMP` is ignored in the comparison.
- `docs/data.json` is rewritten only when content changes, `updated_at` excluded from the comparison (`output.py`); files are written atomically.
- `docs/status.json` (`checked_at`) is written on every successful run, is gitignored and reaches the site only through the Pages artifact: a failed run skips the deploy, so the page keeps showing the last successful check.
- On any failure (`FetchError`, team not found, parse error, invalid document) `fenice-sync` exits 1 and writes nothing, so `data.json`, `calendario.ics` and `status.json` stay as they were. Outputs are built in memory before any write, then written as `.tmp` siblings and moved into place only once all of them exist (`write_all_atomic` in `output.py`), so a failed write leaves all three files as they were.
- Team crests of the opponents are hotlinked from `app.fipavonline.it` (`logo_url`); the page shows the team initials when the image fails or the team has no logo, in the standings as in the team card. Cloudflare answers 403 to the HeadlessChrome user agent: in Playwright headless runs the crests never show, which is not a bug.
- Workflow `sync.yml`: one cron every 4 hours (`17 */4 * * *`), plus push to main and manual dispatch. No hourly run on weekends: user decision of 2026-11-21 (D7). Midweek games can therefore show their result up to 4 hours late. Steps: pytest, `npm test`, `fenice-sync`, commit of `data.json` and `calendario.ics` if changed, `fenice-stamp-sw`, removal of `docs/REPORT_ATTIVITA.md` (the development report must not be published), Pages upload, deploy job. Actions are pinned to commit SHAs.
- Workflow `tests.yml` (on push to main): pytest with coverage, JS tests, ruff, mypy, and `fenice-badges` turns the JUnit and coverage reports into shields.io endpoint JSON, pushed to the one-commit `badges` branch. A red run still publishes, so the badge shows the failure. Badges are produced only by `uv run fenice-badges`, which also writes the error and unknown fallbacks when the reports are missing. The workflow runs `uv run fenice-badges` and falls back to `python3 src/fenice_calendar/badges.py` (stdlib only) when uv cannot start.
- Tests never read `docs/data.json` or the network: they use frozen responses and documents in `tests/fixtures/` (`calendar-64444.json`, `calendar-64353.json`, `standings-*.json`, `data-sample.json`, `data-64353.json`, `posters-19092.json`, `wp-*.json`). CI runs them before the sync, so a FIPAV correction cannot block it.

## Web app

- `docs/index.html` only loads `app.js` (page loading and wiring, with DOM and `fetch` injected, tested in `tests/js/app.test.mjs`); rendering lives in modules that take their data as arguments, with pure rules separated from views: `game-rules.js` (next game, sets, outcome, referees, moved-game labels, map link), `games-view.js` (next-game and last-result boxes, form strip, game list, calendar feed block), `states-view.js` (loading, error and empty boxes, the line of the last check), `calendar-rules.js` (Google Calendar links, `webcal:` feed URL), `view-rules.js` (display wording, `TIME_ZONE` exported once and imported by the views), `standings-rules.js` and `standings-math.js` (standings and possible positions), `tables-view.js` (standings table), `crest-view.js` (team crest image and the initials fallback, for the hero, the standings and the team card), `team-rules.js` and `opponent-rules.js` with `opponent-view.js` (team card), `fenice-rules.js` with `analysis-view.js` (analysis of the Fenice), `notices-view.js`; every view escapes data strings with `esc` from `html.js`, never with a copy of its own. The `webcal:`/https feed links and the page link in the Google Calendar details are derived from the page URL (`feedUrls(pageUrl)` in `calendar-rules.js`): no site URL is hard-coded in JS. `feedUrls` returns `null` on a page not served over http(s), so the feed block is hidden on `file://`. Styles in `styles.css`, plain ES modules, no dependencies.
- Palette and crest: the official logo is `assets/logo-fenice.png` (copy in `docs/logo-fenice.png`); indigo `#2C1B73`, orange-red `#F25034`, gold `#FB9827`, all declared in OKLCH in `styles.css`. Icons in `docs/icons/` and `docs/favicon.ico` are generated from the logo: `uv run --script scripts/make_icons.py` (PEP 723, own Pillow environment, excluded from the project mypy). The apple-touch icon must stay opaque.
- Game lifecycle: `gameStatus(game, now)` in `game-rules.js` is the only place that decides it (`unscheduled` -> `upcoming` -> `live` for `MATCH_WINDOW_MS` after kickoff -> `awaiting` until FIPAV publishes -> `played`). `nextGame`, the row labels (Da giocare / In corso / Risultato in arrivo), the hero, the Google Calendar link (upcoming only) and the team card all ask it; never read `played`/`starts_at` directly in a view.
- Page states (`app.js`): `load` (loading box, then data or error box with Riprova) and `refresh` (background: keeps what is shown on failure) share a ticket, so a stale answer is dropped. Every `CLOCK_TICK_MS` and on `visibilitychange` the page re-renders from the loaded data (countdown, live labels) and, when visible and not mid-load, refreshes data older than `REFRESH_AFTER_MS` (10 min). `applyViews` rewrites only sections whose markup changed, so a tick does not steal focus; the team card gives focus back to the replacement control if its opener was re-rendered. `#list` is not a live region: the error box is `role="alert"`.
- Sections: next game with countdown, last result, standings, analysis of the Fenice, calendar and results (with sets, referees, live link, poster, "moved" badge, add to Google Calendar, ICS feed), committee notices, attribution "Fonte: FIPAV Online" and the date of the last check from `status.json`. Loading, error, empty and populated states are rendered.
- Possible positions (`standings-math.js`): computed in the page starting from `data.standings` (penalties included, as FIPAV publishes them), not from a table rebuilt from results. Every remaining game has 4 outcomes (3-0, 2-1, 1-2, 0-3 with their points). A team is enumerated only over the games that can move it, at most `MAX_ENUMERATED_GAMES` (9): measured 74 ms at 9 games and 285 ms at 10 (`scripts/bench-standings.mjs`); the 0.3 s limit is asserted in `tests/js/standings-math.test.mjs`; above that only the bound on standings points is used, which is never wrong but can be late. A tie on points and wins stays open while the teams involved still have games to play (the later criteria need scores not yet known); the provisional order is wins, set ratio, point ratio. The "Poss." column and the "Già deciso" block appear only once a range is narrower than 1st-last. Games awarded at the table (forfeits) are kept out of set statistics in the analysis; in data.json they are `played` with `sets_won` 3-0 or 0-3 and `sets: []`, the only played games `validate_data` accepts without set scores. The FIPAV shape of such a game is assumed (empty `pt_a`/`pt_b`), not yet seen in a real response: save one in `tests/fixtures/` when it appears.
- Team card (`opponent-view.js`, native `<dialog>`): opens from the next-game box and from team names in the standings (`data-opponent`). Head to head with the Fenice, games left, home/away record. `remainingGames` takes the positions from `data.standings`.
- Installable: `docs/manifest.webmanifest`, icons, service worker `docs/sw.js`. `sw.js` is network first: the cache answers only when the network fails. Every new module imported by the page goes into the `SHELL` of `sw.js`. `tests/test_manifest.py` checks the manifest (relative `start_url` and scope, icons on disk) and the opaque apple-touch icon.
- App version = hash of `docs/` minus FIPAV data and the development report (`appversion.py`), stamped into `sw.js` by `uv run fenice-stamp-sw` in the workflow just before the Pages upload. The repo copy must keep `const VERSION = "dev";`: running the stamp locally rewrites it (restore it), and a second stamp fails on purpose. Not the commit SHA: the data commit every 4 hours would announce a new version each time.
- Update notice (`update.js`, rules in `update-rules.js`): `update.js` exposes `setupUpdates(env)` with service worker, DOM, clock and reload injected, and runs it only where `navigator.serviceWorker` exists; a new worker waits; "Aggiorna" sends `SKIP_WAITING` and every open tab reloads once on `controllerchange`; if the accepted worker turns redundant (a newer release replaced it) the button resets and the newer one is offered; "Più tardi" hides it until the page is loaded again, coming back to the tab or the installed app does not show it (user decision of 2026-11-21). Nothing is shown on a first visit.

## Commands

- `npm run setup`: `uv sync` and import check
- `uv run fenice-sync` (`npm run sync`): fetch calendar, tables, notices and posters; update `docs/data.json`, `docs/calendario.ics` and `docs/status.json`
- `npm test`: JS rules and views (`node --test tests/js/*.test.mjs`, no dependencies)
- `npm run test:py` (`uv run pytest --cov`), `npm run lint` (`uv run ruff check . && uv run mypy`, strict on `src` and `tests`)
- `npm run serve`: static server on `docs/` at port 8000
- `node scripts/bench-standings.mjs`: timing of the possible-positions enumeration, to re-tune `MAX_ENUMERATED_GAMES`
- `uv run fenice-stamp-sw`, `uv run fenice-badges`: used by the workflows only
- Python has no runtime dependencies (stdlib only); dev tools run through uv.
- When FIPAV changes the response shape, save the new response in `tests/fixtures/` and reproduce the failure there first.
